# ESCALA

Framework para disenar escaleras de valor B2B que maximizan el revenue por cliente a traves de una secuencia de ofertas ascendentes, basado en DotCom Secrets de Russell Brunson adaptado a contextos B2B LATAM.

## Filosofia: Quien Puede Gastar Mas, Gana

> "La empresa que puede gastar mas para adquirir un cliente, gana." — Dan Kennedy

Esta es la ley fundamental de la adquisicion. No gana quien tiene el mejor producto, sino quien puede pagar mas por cada lead, por cada click, por cada impresion. La unica forma de poder gastar mas es tener un **backend rentable** que financie tu frontend.

La mayoria de las empresas B2B cometen el error de tener una sola oferta a un solo precio. ESCALA rompe ese patron disenando una secuencia donde cada tier financia el siguiente y cada cliente tiene un camino claro de ascension.

## ESCALA = Estrategia de Conversion Ascendente con Leverage Automatico

El acronimo ESCALA captura los principios del sistema:

- **E** — Estrategia de ofertas en capas, no productos aislados
- **S** — Secuencia disenada de ascension (no aleatoria)
- **C** — Conversion en cada tier con metricas claras
- **A** — Ascension trigger entre tiers (automatico o asistido)
- **L** — Leverage del backend para financiar el frontend
- **A** — Automatico en las capas inferiores, high-touch en las superiores

## Los 4 Tiers de ESCALA

### Tier 1: BAIT (FREE)

| Atributo | Detalle |
|----------|---------|
| **Proposito** | Atraer al dream customer, demostrar expertise, capturar datos |
| **Precio** | $0 (gratis) |
| **Tipos de producto B2B** | Lead magnet, assessment gratuito, quiz funnel, template descargable, webinar, mini-curso |
| **Tiempo de consumo** | 5-15 minutos |
| **Metrica clave** | Leads capturados, costo por lead (CPL) |
| **Ascension trigger** | El prospect consume el bait y ve que resuelve un problema parcialmente → quiere la solucion completa |

**Principio**: El bait debe resolver un problema **real** pero **parcial**. Suficiente valor para generar confianza, pero deja claro que hay mas.

### Tier 2: FRONTEND ($)

| Atributo | Detalle |
|----------|---------|
| **Proposito** | Convertir lead en cliente, cubrir costos de adquisicion, establecer relacion transaccional |
| **Precio B2B** | $97-$497 (LATAM: $47-$297) |
| **Tipos de producto B2B** | Workshop grabado, playbook, toolkit digital, diagnostico basico, audit express |
| **Tiempo de consumo** | 1-5 horas |
| **Metrica clave** | Tasa de conversion, revenue por lead, tiempo a primera compra |
| **Ascension trigger** | El cliente implementa el frontend y obtiene resultados parciales → necesita implementacion guiada |

**Principio**: El frontend puede ser breakeven o incluso perder dinero. Su funcion es **crear clientes**, no generar profit. El profit viene del middle y backend.

### Tier 3: MIDDLE ($$)

| Atributo | Detalle |
|----------|---------|
| **Proposito** | Entregar implementacion, generar profit, construir caso de exito |
| **Precio B2B** | $1,000-$5,000 (LATAM: $500-$3,500) |
| **Tipos de producto B2B** | Programa de implementacion, consultoria de N semanas, grupo mastermind, certificacion, sistema llave en mano |
| **Tiempo de consumo** | 4-12 semanas |
| **Metrica clave** | Margen bruto, completion rate, NPS, caso de exito generado |
| **Ascension trigger** | El cliente ve resultados concretos y quiere escalar → necesita solucion personalizada y continua |

**Principio**: El middle es donde empieza el profit real. Aqui validas que tu solucion genera resultados medibles. Cada cliente de middle deberia convertirse en un caso de exito.

### Tier 4: BACKEND ($$$)

| Atributo | Detalle |
|----------|---------|
| **Proposito** | Maximizar LTV, crear relacion de largo plazo, generar revenue recurrente |
| **Precio B2B** | $5,000-$50,000+/ano (LATAM: $3,000-$30,000+/ano) |
| **Tipos de producto B2B** | Retainer mensual, advisory board, programa anual, licencia enterprise, done-for-you, equity deal |
| **Tiempo de consumo** | 6-12+ meses (relacion continua) |
| **Metrica clave** | LTV, churn rate, expansion revenue, margen neto |
| **Ascension trigger** | N/A (tier maximo) — el objetivo es retener y expandir |

**Principio**: El backend es el multiplicador de todo el sistema. Un backend fuerte permite pagar mas por leads en el frontend, lo cual te da ventaja competitiva en adquisicion.

## RADAR: Descubre a Tu Dream Customer

Antes de disenar la escalera de valor, necesitas saber exactamente a quien le vendes. RADAR responde 4 preguntas fundamentales:

### Las 4 Preguntas RADAR

| # | Pregunta | Que descubres |
|---|----------|---------------|
| 1 | **WHO** — Quien es tu dream customer? | El cliente que obtiene mas valor de tu solucion, paga sin objeciones, y refiere a otros |
| 2 | **WHERE** — Donde se congregan? | Canales, comunidades, eventos, publicaciones donde puedes alcanzarlos |
| 3 | **BAIT** — Que cebo los atrae? | El lead magnet o oferta gratuita que resuelve su dolor mas inmediato |
| 4 | **RESULT** — Que resultado les prometes? | La transformacion especifica y medible que tu escalera de valor entrega |

### Implementacion de RADAR

**Paso 1 — WHO**: Revisa tus mejores 10 clientes. Que tienen en comun? Industria, tamano, cargo del comprador, dolor, presupuesto. Si usaste ICP Analysis, este paso ya esta resuelto.

**Paso 2 — WHERE**: Lista 10 lugares donde tu dream customer pasa tiempo profesional. LinkedIn groups, podcasts, newsletters, conferencias, Slack communities, asociaciones. Prioriza por concentracion (no por tamano).

**Paso 3 — BAIT**: Que problema urgente y especifico puedes resolver en 5-15 minutos? El bait debe ser tan bueno que el prospect piense: "Si esto es lo gratis, que tan bueno sera lo pagado?"

**Paso 4 — RESULT**: Describe la transformacion en una oracion: "Ayudo a [WHO] a lograr [RESULTADO] en [TIMEFRAME] sin [OBJECION COMUN]."

Para la metodologia completa y el modelo de 4 tiers detallado, leer `frameworks/escala-framework.md`.

## Product-Funnel Fit

Cada tier de ESCALA necesita un producto disenado especificamente para ese nivel de la escalera. No se trata de empaquetar lo mismo a diferentes precios — se trata de disenar productos que creen ascension natural.

Para la matriz de priorizacion de features y criterios de diseno por tier, leer `frameworks/product-funnel-fit.md`.

## Modelado LTV:CAC

La salud de tu escalera de valor se mide con un numero: **LTV:CAC ratio**. Es el ratio entre el valor de vida del cliente y el costo de adquirirlo.

### Formulas basicas

```
LTV = (Revenue Frontend + Revenue Middle + Revenue Backend) x Tasa de Retencion
CAC = (Inversion en Ads + Costos de Funnel + Comisiones) / Clientes Adquiridos
Revenue Per Lead = LTV x Tasa de Conversion Global
```

### Benchmarks rapidos

| LTV:CAC | Diagnostico |
|---------|-------------|
| < 1:1 | Perdiendo dinero — la escalera no funciona |
| 1-2:1 | Breakeven — estas pagando por aprender, no por crecer |
| 3-5:1 | Rentable — zona de escalado |
| > 5:1 | Dominando — puedes outspend a toda la competencia |

Para formulas completas, escenarios y ajustes LATAM, leer `patterns/ltv-cac-calculator.md`.

## Integracion SPICED

| SPICED | Conexion con ESCALA |
|--------|---------------------|
| **Situation** | Define en que tier deberia entrar el prospect segun su situacion actual |
| **Pain** | Cada tier resuelve un nivel de dolor: bait (dolor superficial), backend (dolor estructural) |
| **Impact** | El impacto escala con cada tier: bait (quick win), frontend (resultado parcial), middle (transformacion), backend (ventaja competitiva) |
| **Critical Event** | El trigger de ascension entre tiers funciona como critical event interno |
| **Decision** | El decision process cambia por tier: self-serve (bait/frontend) vs. committee (middle/backend) |

## Conexiones con otros skills

- **ICP Analysis** → Define WHO en RADAR. Sin ICP claro, ESCALA no tiene fundamento
- **Quiz Funnel** → El quiz ES un bait de Tier 1. Segmenta prospects para dirigirlos al frontend correcto
- **Discovery Mastery** → Discovery calls califican prospects para middle y backend. SPICED score indica tier apropiado
- **Copywriting Engine** → Copy de landing pages, emails de ascension, paginas de oferta por tier
- **Pipeline Management** → Cada tier mapea a una etapa de pipeline. El pipeline refleja la escalera

## Output esperado

Al completar el proceso de ESCALA, el usuario obtiene:

1. **RADAR completo** — WHO, WHERE, BAIT, RESULT definidos y validados
2. **Escalera de 4 tiers** — Cada tier con producto, precio, metricas y ascension trigger
3. **Modelo LTV:CAC** — Proyeccion con escenarios conservador, moderado y agresivo
4. **Mapa de ascension** — Journey visual del cliente desde bait hasta backend
5. **Product-funnel fit** — Priorizacion de features por tier
