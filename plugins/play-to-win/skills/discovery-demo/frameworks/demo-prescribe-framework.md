# Framework: Demo & Prescribe

Coreografia completa para ejecutar demos que prescriben soluciones alineadas a dolores reconocidos. Cada punto del demo conecta directamente con un dolor validado en discovery, transformando la presentacion de "mira lo que hacemos" a "asi resolvemos lo que te duele". Basado en el Blueprint #24 de Winning by Design (How to Demo).

## Principios fundamentales

- **El demo es una prescripcion, no una exhibicion** — Solo mostrar lo que resuelve dolores validados
- **Un dolor a la vez** — Cada demo point aborda un solo dolor reconocido (5-7 minutos)
- **La conexion con discovery es obligatoria** — "Antes compartiste que..." es la frase mas poderosa del demo
- **Las preguntas de impacto reemplazan el pitch** — En vez de decir "esto es genial", preguntar "como impactaria esto?"
- **Los criterios de decision emergen del impacto** — No se imponen, se construyen durante el demo

## Coreografia del Demo

El demo sigue una secuencia precisa de 12 momentos. Cada momento tiene un proposito especifico y una transicion natural al siguiente.

```
┌─────────────────────────────────────────────────────────────────┐
│                    COREOGRAFIA DEL DEMO                         │
│                                                                 │
│  PREP ──> SETUP ──> ACE/Agenda ──> Layout ──> SPICED Summary   │
│                                                        │        │
│                                                        ▼        │
│                                                   Demo Point 1  │
│                                                   (5-7 min)     │
│                                                        │        │
│                                                        ▼        │
│                                                   Demo Point 2  │
│                                                   (5-7 min)     │
│                                                        │        │
│                                                        ▼        │
│                                                   Demo Point 3  │
│                                                   (5-7 min)     │
│                                                        │        │
│                                                        ▼        │
│  Close <── Wagons <── Recap <── Decision <── Impact Qs          │
└─────────────────────────────────────────────────────────────────┘
```

### Momento 1: PREP (antes del demo)

Preparacion completa antes de encender la camara:

- [ ] Identificar 3 dolores validados del discovery para convertir en demo points
- [ ] Seleccionar 1 historia de use-case por demo point
- [ ] Preparar preguntas de impacto especificas para cada dolor
- [ ] Pre-cargar todas las pestanas/pantallas necesarias
- [ ] Limpiar el escritorio virtual — nada que no sea parte del demo

### Momento 2: SETUP (primeros 2 minutos)

Verificacion tecnica y ambiental:

- [ ] Audio y video funcionando correctamente
- [ ] Screen share listo pero NO activado todavia
- [ ] Notas del discovery a la mano (no en pantalla)
- [ ] Timer configurado para controlar duracion de cada demo point
- [ ] Backup plan si la conexion falla (slides PDF, screenshots)

### Momento 3: ACE/Agenda

ACE adaptado al contexto de demo:

**A — Appreciate**:
> "Gracias por darnos la oportunidad de mostrarles como podriamos resolver [dolor principal]. Se que evaluar opciones toma tiempo valioso."

**C — Check End Time**:
> "Tenemos 45 minutos agendados. Sigue bien ese tiempo?"

**E — End Goal**:
> "Mi objetivo hoy es mostrarles concretamente como resolvemos los 3 desafios que identificamos juntos, y que al final tengan claridad sobre si tiene sentido avanzar a los siguientes pasos."

**Agenda del demo**:
> "Vamos a cubrir 3 puntos alineados a lo que conversamos: [dolor 1], [dolor 2], y [dolor 3]. Despues haremos un recap y definimos juntos los siguientes pasos. Les parece bien?"

### Momento 4: Layout — Orientar al cliente

Antes de mostrar nada funcional, orientar al cliente sobre lo que va a ver en pantalla.

**Script**:
> "Antes de entrar, dejame orientarlos sobre lo que van a ver. En la pantalla van a ver [descripcion general]. A la izquierda esta [elemento], arriba [elemento], y el area principal es donde [funcion]. Todo claro hasta ahi?"

**Mejores practicas de layout**:
- Pre-cargar todas las pestanas en orden de presentacion
- Pantalla limpia — sin notificaciones, sin pestanas irrelevantes
- Datos reales o realistas — nunca "Lorem ipsum" o datos de prueba obvios
- Si es posible, usar datos que reflejen la industria del prospect
- Zoom al area relevante — no esperar que el prospect busque donde mirar

### Momento 5: SPICED Summary — Conexion con discovery

Este es el puente critico entre discovery y demo. Resumir los hallazgos del discovery para que el prospect confirme que los dolores siguen vigentes.

**Script**:
> "Antes de mostrar nada, quiero confirmar que estamos alineados. En nuestra conversacion anterior compartiste que [Situacion], y que eso les causaba [Pain 1] y [Pain 2]. El impacto que identificamos fue [Impact]. Y mencionaste que necesitaban resolverlo para [Critical Event]. Sigue siendo asi?"

**Por que es critico**:
- Revalida los dolores — si cambiaron, puedes ajustar el demo en tiempo real
- Demuestra que escuchaste en el discovery (credibilidad)
- Establece el marco de evaluacion: "vamos a resolver ESTO"
- Si hay nuevos participantes, los pone en contexto

## Preparacion (PREP)

La preparacion del demo tiene 3 ejes:

### Eje 1: Conocer tus demo points

| Demo Point | Dolor que resuelve | Historia de use-case | Pregunta de impacto |
|------------|-------------------|---------------------|---------------------|
| Demo 1 | ___ | ___ | ___ |
| Demo 2 | ___ | ___ | ___ |
| Demo 3 | ___ | ___ | ___ |

### Eje 2: Preparar el entorno

- **Pestanas pre-cargadas**: Tener cada demo point en una pestana separada, en orden
- **Datos relevantes**: Usar datos que reflejen la industria/tamano del prospect
- **Backup**: Tener screenshots o slides como respaldo si algo falla
- **Timer**: Configurar alarma silenciosa a los 5 minutos de cada demo point

### Eje 3: Preparar la narrativa

Para cada demo point, tener preparado:
1. **Frase puente** desde el dolor: "Antes compartiste que [dolor]..."
2. **Demo**: Mostrar la solucion en accion (2-3 minutos)
3. **Historia**: Use-case de cliente similar (30-60 segundos)
4. **Pregunta de impacto**: "Como impactaria esto en [metrica]?"

## Layout: Orientar al Cliente

El layout no es solo una cortesia — es una tecnica de control de atencion. Si el prospect no sabe donde mirar, pierde el contexto de lo que muestras.

### Principios del layout

- **Orientar antes de navegar** — Explicar la pantalla antes de hacer clic en nada
- **Zoom al area relevante** — No mostrar la pantalla completa si solo importa una seccion
- **Narrar la navegacion** — "Ahora voy a ir a [seccion] para mostrarles [funcion]"
- **Pausar despues de cada transicion** — Dar 3 segundos para que procesen

### Tab-based selling

Organizar el demo en pestanas pre-cargadas:
- **Tab 1**: Dashboard/vista general (para layout)
- **Tab 2**: Demo Point 1 (dolor principal)
- **Tab 3**: Demo Point 2 (segundo dolor)
- **Tab 4**: Demo Point 3 (tercer dolor)
- **Tab 5**: Resultados/metricas (para impacto)

## Conexion SPICED

El SPICED Summary es el puente que conecta discovery con demo. Sin este puente, el demo es una presentacion generica.

### Formula de conexion

```
"En nuestra conversacion anterior..."

Situation: "...compartiste que [contexto de la empresa]"
Pain:      "...y que eso les causaba [dolor 1] y [dolor 2]"
Impact:    "...lo cual impactaba en [metrica/resultado]"
C. Event:  "...y mencionaste que necesitaban resolverlo para [fecha/evento]"
Decision:  "...con [personas] involucradas en la evaluacion"

"...Sigue siendo asi?"
```

### Reglas de la conexion

- **Usar las palabras del prospect** — No tu vocabulario de producto
- **Maximo 60 segundos** — Es un resumen, no una recapitulacion completa
- **Terminar con pregunta** — Siempre validar que sigue vigente
- **Si hay nuevos participantes** — Pedir al champion que confirme para educar a los nuevos

## Demo Structure: Un Dolor a la Vez

Cada demo point sigue una estructura identica de 5-7 minutos. La disciplina de un dolor a la vez evita el error fatal de mostrar 20 features sin conectar ninguna con un problema real.

### Demo Point 1 (5-7 minutos)

**Frase puente**:
> "El primer desafio que mencionaste fue [dolor 1]. Dejame mostrarte como lo resolvemos."

**Mostrar solucion** (2-3 min):
- Navegar a la funcionalidad relevante
- Demostrar el flujo de trabajo en 3-5 clics maximo
- Narrar cada paso: "Aqui es donde [accion] para resolver [dolor]"
- Pausar en el momento de mayor impacto visual

**Compartir historia** (30-60 seg):
> "Un cliente nuestro en [industria], [nombre si se puede], tenia exactamente este problema. Implementaron esto y en [tiempo] lograron [resultado cuantificable]."

**Preguntar impacto**:
> "Puedes verte usando esto en tu dia a dia?"
> "Como crees que esto impactaria en [metrica que mencionaron]?"

### Demo Point 2 (5-7 minutos)

**Frase puente**:
> "El segundo tema que exploramos fue [dolor 2]. Mira como abordamos esto."

[Misma estructura: Mostrar → Historia → Preguntar impacto]

### Demo Point 3 (5-7 minutos)

**Frase puente**:
> "Y el tercer desafio, [dolor 3], es algo que resolvemos asi."

[Misma estructura: Mostrar → Historia → Preguntar impacto]

### Transiciones entre demo points

- **No preguntar "alguna pregunta?" entre puntos** — Rompe el momentum
- **Usar transiciones naturales**: "Ahora que vimos como resolvemos [dolor 1], pasemos a [dolor 2]..."
- **Si surge una pregunta espontanea** — Responder brevemente y volver a la estructura

## Impact Questions During Demo

Las preguntas de impacto reemplazan al pitch. En vez de decir "esto es increible", preguntar:

### 3 Preguntas clave

| Pregunta | Proposito | Momento |
|----------|-----------|---------|
| "Puedes verte usando esto?" | Evaluar adoption readiness | Despues de mostrar cada demo point |
| "Esto te ayudaria con [dolor validado]?" | Reconexion con pain | Despues de la historia de use-case |
| "Como impactaria esto en [metrica]?" | Cuantificar valor percibido | Cierre de cada demo point |

### Preguntas de impacto avanzadas

- "Si tuvieras esto hoy, que cambiaria en tu operacion la proxima semana?"
- "Cuantas horas a la semana le ahorraria esto a tu equipo?"
- "Que le dirias a tu [jefe/board] sobre el impacto de esto?"

### Critical Event durante el demo

Revalidar urgencia:
> "Mencionaste que necesitaban una solucion para [fecha]. Con lo que has visto, crees que esto les permitiria llegar a esa fecha?"

Pregunta de consecuencias:
> "Que pasa si no llegan a esa fecha? Cual es el costo de no actuar?"

## Decision Criteria from Impact

Los criterios de decision no se imponen — emergen naturalmente de las preguntas de impacto durante el demo.

### Como se construyen

```
Dolor validado ──> Demo point ──> Impact question ──> Respuesta del prospect
                                                              │
                                                              ▼
                                                    Criterio de decision
```

**Ejemplo**:
- Dolor: "Perdemos deals porque el ciclo de venta es muy largo"
- Demo: Mostrar como se acorta el ciclo
- Impact Q: "Cuanto impactaria reducir el ciclo de 90 a 60 dias?"
- Respuesta: "Seria enorme, podriamos cerrar 30% mas deals"
- Criterio: **Capacidad de reducir ciclo de venta** (ponderacion alta)

## Recap & Wagons

El cierre del demo conecta lo mostrado con los siguientes pasos.

### Mirar atras (Recap)

> "Recapitulemos. Hoy cubrimos 3 areas: [dolor 1] y como lo resolvemos con [solucion 1], [dolor 2] con [solucion 2], y [dolor 3] con [solucion 3]. Abordamos lo que necesitaban?"

### ACE Follow-up

Volver al End Goal original:
> "Al principio dijimos que el objetivo era que tuvieran claridad sobre si tiene sentido avanzar. Como se sienten al respecto?"

### Mirar adelante (Next Steps)

> "Basado en lo que vimos, el siguiente paso natural seria [propuesta concreta]. Que les parece?"

**Opciones de next steps**:
- Proof of concept / trial
- Technical deep-dive con el equipo tecnico
- Reunion con decision maker / sponsor ejecutivo
- Propuesta formal con pricing

### Orchestrate (Expandir)

> "Para maximizar el valor de la siguiente reunion, seria util tener a [persona/rol]. Puedes invitarlo?"

### Involve Others

- Identificar stakeholders que no estuvieron en el demo pero deberian estar en la decision
- Pedir al champion que facilite la introduccion
- Ofrecer un resumen ejecutivo para compartir internamente

## Demo Variations

### Product Demo (en vivo)

- Mostrar el producto real funcionando
- Datos relevantes pre-cargados
- Backup: screenshots si hay problemas tecnicos
- Mejor para: Compradores tecnicos, equipos de implementacion

### Deck Pitch (slides)

- Slides con capturas + narrativa
- Ideal cuando no hay producto para demostrar o cuando el prospect es C-level
- Estructura: Dolor → Solucion visual → Resultado → Historia
- Mejor para: Sponsors ejecutivos, primeras reuniones

### Use-case Prescription (consultivo)

- Sin producto ni slides — solo conversacion basada en casos
- "Si tuvieran [solucion], su flujo seria: paso 1, paso 2, paso 3..."
- Mejor para: Deals complejos, servicios profesionales, consultoria

## Errores comunes

| Error | Consecuencia | Correccion |
|-------|-------------|------------|
| Mostrar features sin conectar a dolores | El prospect no ve valor — "interesante pero no para nosotros" | Siempre empezar con "Antes compartiste que [dolor]..." |
| Demo de mas de 7 minutos por punto | Atencion cae, se pierde el impacto | Timer estricto de 5-7 minutos por demo point |
| No hacer preguntas de impacto | No sabes si el prospect ve valor | Despues de cada demo point: "Como impactaria esto?" |
| Mostrar 10 features en vez de 3 puntos | Overwhelm — el prospect no recuerda nada | Maximo 3 demo points, uno por dolor validado |
| No conectar con discovery | El demo se siente generico | SPICED Summary obligatorio antes del primer demo point |
| Saltarse el layout | El prospect se pierde en la interfaz | Orientar: "A la izquierda ven X, arriba Y, el area principal es Z" |
